# project-intake

一套给「人 + AI 协作开发项目」用的**立项分诊与流程规范**，已编译为可直接使用的 AI 技能。

- **解决什么**：想法模糊就开始开发 → 返工 / 做废；流程繁琐压死小项目；AI 自己论证自己。
- **怎么用**：新项目开场只说一句话想法，技能自动三问定档（微 / 小 / 中 / 大），按档位执行对应强度的流程。
- **核心设计**：入口常驻、全文按需——微/小档不读完整规范，几乎零额外开销。

当前版本：**v1.6**。

## 安装

方式一（推荐，作为技能安装）：

```bash
# 用户级技能目录，跨项目可用
git clone https://github.com/narikujrd/project-intake.git ~/.workbuddy/skills/project-intake
```

方式二：手动把本仓库的 `project-intake/` 目录内容复制到 `~/.workbuddy/skills/project-intake/`。

目录结构：

```
project-intake/
├── SKILL.md                    # 常驻入口：三问定档 + 微/小档细则 + 全档铁律
└── references/
    ├── 规范-v1.6.md            # 完整规范全文（中/大档按需加载）
    └── 安全审查清单.md         # 涉外部模型 / 账号 / 密钥时的必答 8 节（按需加载）
```

## 三问定档

收到任意一个项目想法时，一次性问完，禁止分多轮追问：

| # | 问题 | 判读 |
|---|---|---|
| Q1 | 需要你提供密钥 / 付费 / 注册账号 / 审批吗？ | 需要 → 至少「小」档 |
| Q2 | 预计开发工作量超过 1 天吗？ | 超过 → 至少「小」档 |
| Q3 | 做错了会有实际损失吗？（花钱 / 对外承诺 / 影响他人） | 会有 → 至少「小」档 |

| 档 | 判据 | 流程强度 |
|---|---|---|
| 微 | 三问全否 | 无文档，直接做，交付 3 行说明 |
| 小 | 任一为是，总量 ≤2 周 | 合并一次对话 + 半页竞品速查 + 一次拍板，1–2 页 |
| 中 | 超过 2 周 / 多模块 / 关键路径外部依赖 | S0–S6 全流程 |
| 大 | 同上且周期长 | 全流程 + 门 1.5 + 逐模块预验尸与探针 |

**档位宁可定高半档，不可定低半档**：升档的成本是几轮对话，降档出错的成本是返工甚至废弃。

## 全档位铁律（摘要）

1. **禁止静默替换方案路径**——官方接口改爬虫、付费改免费替代等任何降级，必须单列上报原因 / 成本变化 / 合规等级变化 / 备选路径。凭证类依赖的降级行为要写死进代码，不能靠人记住。
2. **义务清单制**——凡「只有老板能给」的东西（账号、密钥、付费、审批、数据授权）强制列出，含时间、成本、持续性、不提供的后果；义务项要写到「在哪做」才算可执行。
3. **一次收齐、一次拍板**——决策批量提交，每项带推荐 + 默认值。
4. **结论前置**——每份产物开头一句话结论 + 三行要点；找不到结论的文档打回重写。
5. **老板也是变更申请方，无特权**。
6. **默认 NO-GO**——过门必须拿出证据推翻默认，且写下「我最担心的点」。
7. **角色隔离**——审查不得由提案方兼任，做不到就声明可信度打折。
8. **关键外部前提先实测，再动手**——模型能力、接口跨域、限额上限一律查官方文档或实测，禁止凭印象推断；外部模型名 / 接口版本严禁硬编码进配置。

完整机制（八件套）、阶段细则 S0–S6、三道门标准、模板附录 A–F 见 `references/规范-v1.6.md`。

## 涉及外部依赖时的安全审查

方案里出现**外部模型 API、外部平台账号、密钥凭证、浏览器登录态**任意一项时，触发 8 节必答清单，完整内容见 `references/安全审查清单.md`。

最容易颠倒顺序的三条：

1. **先划权限边界，再谈防御**——先写死「模型没有任何权限」，多数防御需求会自动消失。
2. **按资产价值排序，不按「听起来吓人」排序**——平台登录态（账号劫持）通常远高于 API key（只是烧钱）。
3. **凭证不进第三方依赖的子进程环境**——自家脚本与三方工具共用 `process.env`，是最容易漏、后果最实的一处。

## 维护

规范升版时需同步三处：本地规范文件 → 技能内 `references/` 副本 → 远端归档。`references/` 副本不同步会导致技能行为与规范不符。
