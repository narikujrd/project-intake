# AI 项目立项开发标准流程(基础规范 v1.4)

> **定位**:以"老板 + AI 多岗位"的协作形态,建立从模糊想法到交付的标准流水线。
> **目标**:对齐颗粒度,减少不必要的时间和资源浪费。
> **性质**:通用基础模板。**先读 §0 定档,再按档位取用后续章节**——不按档位取用,规范本身就会变成浪费。

---

## 0. 入口分流:先定档,再走流程

**分流先于流程。** 用大流程干小事,和用小流程干大事,同样是浪费。所以第一步不是启动流程,而是判断这个项目配不配得上流程。

### 0.1 三问定档(S0 结束时,AI 一次性问完)

| # | 问题 | 判读 |
|---|---|---|
| Q1 | 需要你提供密钥 / 付费 / 注册账号 / 审批吗? | 需要 → 至少"小"档 |
| Q2 | 预计开发工作量超过 1 天吗? | 超过 → 至少"小"档 |
| Q3 | 做错了会有实际损失吗?(花钱 / 对外承诺 / 影响他人) | 会有 → 至少"小"档 |

**三问全否 → 微项目档;任一为是 → 至少"小"及以上**;多模块 / 多人协作 / **关键路径依赖外部平台或数据源(其可用性决定项目生死)** → 直接"中"档。
◆注意:仅使用单个免费/自有 API 不算"关键路径依赖"——依赖的数量与生死攸关程度才是定档依据,不是"有没有依赖"。

### 0.2 三档对照

| 档 | 判据 | 走什么 | 产物 | 保留的机制 |
|---|---|---|---|---|
| **微**(≤1 天) | 三问全否 | 一句话想法 → AI 一句话复述确认 → 直接做 → 交付时 3 行说明 | **无文档** | 仅两条底线(见 0.3) |
| **小**(1 天–2 周) | 任一为是,总量 ≤2 周 | S0+S1 合并为一次对话 → S2 半页竞品速查 → 合并门(一次拍板)→ 交付 | 1–2 页 | 复述确认、轻量决策包、路径降级告知、义务提醒 |
| **中**(2 周–3 月) | 超过 2 周 / 多模块 / 关键外部依赖 | S0–S6 全流程;S2 可压缩为半页竞品速查 | 5–8 份 | 八机制全开 |
| **大**(长期 / 多模块) | 同上且周期长 | 全流程 + 门 1.5 + 模块化预验尸 | 按模块 | 全部 + 逐模块探针 |

### 0.3 微项目档:不叫立项,但两条底线不能省

微项目**没有门、没有文档、没有岗位表、没有决策包**。你提想法,AI 复述确认理解无误,直接交付。但下面两条每条只占一行字,而踩坑代价最高,所以不省:

1. **路径不一致必须一句话告知**:原计划的做法行不通、要换做法(官方接口 → 自己写 / 爬虫 / 手工),必须当场说一句。
2. **要你出钱、出账号、出时间必须一句话告知**:注册、付费、授权、需要你每天操作,必须当场说一句。

这两条挡掉的,是所有浪费里最贵的两类:**在错误信息下做的批准**,和**没人告知的隐性支出**。其余步骤对微项目都是仪式。

### 0.4 档位定错的处理

档位不是一锤定音。做起来才发现超预期(比如微项目里冒出要付费的服务)→ **当场升档**,把新档位该补的东西补上,而不是硬着头皮走完轻流程。

## 1. 核心原则(六条,不可裁剪)

1. **模糊想法不得直接进入开发。** "我想做个 X"是输入,不是立项依据。
2. **默认 NO-GO。** 每道决策门默认否决;要过门,必须拿出证据推翻默认。
3. **人的注意力是唯一稀缺资源。** AI 劳动力近乎无限,老板的决策带宽有限——所有决策批量收齐,禁止挤牙膏式追问。
4. **提案与审查分离。** 提案的 AI 与审查的 AI 必须隔离(不同会话/不同上下文),禁止自己论证自己。
5. **产物文件化。** 每阶段产出落盘为文件;流程可追溯、可复现,不依赖聊天记录。
6. **门是审查,不是签字。** ◆v1.3 过门时老板必须至少指出一个不确定点或异议,并写下"我最担心的点";否则该次过门记为"未审阅",风险由老板显式承接。**门的价值取决于它的过滤效率,不取决于它的数量。**

## 2. 角色体系(虚拟岗位)

| 岗位 | 职责 | 出场阶段 | 关键产物 |
|---|---|---|---|
| **老板(你)** | 唯一决策者,只在三道门出现 | 门 0 / 门 1 / 门 2 | 拍板结果 |
| 产品经理 | 需求解读、问题定义、需求文档 | S0–S5 | 问题定义书、需求文档 |
| 市场分析 | 竞品调研、差异化判断 | S2 | 竞品速查 |
| 技术负责人 | 技术可行性、架构、选型 | S4–S6 | 技术方案 |
| 财务 | 成本区间、投入产出 | S4 | 成本模型 |
| 法务/合规 | 合规风险、许可 | S4 | 合规清单 |
| PMO | 岗位排布、流程、里程碑 | S3、S6 | 开发指导文档、排期 |
| **红队审查** | 独立评审、预验尸 | S5、每批小评审 | 缺陷清单、风险预案 |
| 执行岗 | 具体开发 | S6 | 交付物 |

**三条铁律**:
- 红队审查岗**永远不得由提案岗兼任**。
- 老板在门之外的阶段只接收简报,不参与产出。
- **隔离必须声明落地方式** ◆v1.3:①新会话/新上下文;**②时间隔离**——提案封存,隔轮再以"只看产物"模式审查;**③老板做隔离代理**——提案理由留在老板手里,只把产物交给审查方。三者都做不到时,必须显式声明"本次审查为对抗式自审,可信度打折",并据此降低审查结论的采信权重。**假装隔离比不隔离更危险。**

## 3. 流程总览

```
S0 想法捕获
  ↓
S1 需求解读与问题定义  ◆复述确认制
  ↓
S2 机会扫描
  ↓
【门 0】值不值得做 ——— 老板决策(GO / NO-GO / PIVOT)
  ↓
S3 岗位与流程设计  ◆决策点标注 → 产物:开发指导文档
  ↓
S4 分岗可行性分析  ◆决策包制 → 产物:老板决策包
  ↓
S5 执行方案与红队评审  ◆角色隔离·预验尸 → 产物:执行方案+风险预案
  ↓
【门 1】开工授权 = 正式立项 ——— 老板决策(GO / 条件GO / NO-GO)
  ↓                                    产物:项目章程
S6 开发交付  ◆变更与降级上报通道(分批执行 + 每批小评审 + 外部环境检查)
  ↓
【门 2】验收发布 ——— 老板决策(GO / 返工)
```

## 4. 阶段细则

### S0 想法捕获
- **输入**:老板三句话——想做什么 / 给谁用 / 为什么是现在。
- **AI 动作**:生成"补问清单",**一次性问完**,禁止分多轮追问。
- **产物**:想法卡(一页)。
- **完成标准**:想法可被第三方复述,且**不含解决方案**。
- **常见坑**:老板一开始就讲技术方案 → 先拿掉,记入 S5 待办。

### S1 需求解读与问题定义 ◆复述确认制
- **AI 动作**:用自己的话复述需求 → 老板确认"是 / 不是 / 偏了"。复述通过后,产出问题陈述:**谁、什么场景、什么痛点、现有方案为何不够**。
- **三次对齐点** ◆v1.3(解决"老板点头了但其实理解错"):① S1 AI 正述 → 老板确认;② S5 **反向复述**——老板用自己的话讲一遍"我要交付的东西是什么",AI 对照方案找偏差;③ 门 1 章程的"目标一句话"由老板亲手确认措辞。
- **产物**:问题定义书。
- **完成标准**:目标用户具体到角色;"现有方案为何不够"有明确答案;三次对齐点全部完成。
- **常见坑**:把"我想做的功能"当"用户的问题";只做一次复述就以为对齐了——**老板自己没想清楚时,第一次确认必然失真**。

### S2 机会扫描
- **AI 动作**:调研是否已有相同产品;有的话,差异化在哪;没有的话,是蓝海还是没人需要。**数据类项目必须额外调研数据源质量与"水分"**——榜单是否有买榜/刷量,是公开行业常识就必须带出。
- **产物**:竞品速查(一页:竞品 / 定位 / 短板 / 我们的差异)。
- **完成标准**:能回答"为什么是我们"。
- **常见坑**:把"没人做过"当机会——更常见的原因是没人需要;只调研竞品不调研数据源——数据类项目的死因往往在数据本身。

### 【门 0】值不值得做
- **AI 提交**:推荐结论 + 支持证据 + **反面证据**(必须提供,防止 AI 迎合老板)。
- **老板三选一**:GO(进 S3)/ NO-GO(一页纸归档,不恋战)/ PIVOT(改方向,回 S1)。

### S3 岗位与流程设计 ◆决策点标注
- **AI 动作**:按项目定制虚拟岗位表、阶段依赖、交付顺序;**标注老板决策点**——区分"必须老板拍板"与"AI 可自主、事后报备";同时**初排《老板义务清单》**——凡是只有老板能提供的资源(账号、密钥、审批、数据授权、付费)先列出已知项。
- **产物**:项目开发指导文档。
- **完成标准**:每个后续产物有唯一责任岗位;老板决策点 ≤ 10 个。
- **常见坑**:岗位表照抄通用模板,不按项目裁剪。

### S4 分岗可行性分析 ◆决策包制
- **AI 动作**:各岗位并行分析(技术可行性 / 成本区间 / 合规风险 / 需求边界),汇总为《老板决策包》;技术负责人**必须列出全部外部依赖**(第三方服务、API key、配额限制、运行环境),财务岗核算对应成本,**汇总为《老板义务清单》**——老板不需要预知这些,挖出来是岗位的强制职责。
- **路径披露与降级上报** ◆v1.3(直接回应"原以为用官方接口,结果必须爬虫"):技术负责人必须**逐项披露每个能力/数据源的实际实现路径**,并标注是否发生降级或替换——官方接口 → 爬虫、付费服务 → 免费替代、云托管 → 自建、标准方案 → hack。**任何降级/替换必须单列上报**,附:①为什么原路径不可行;②成本变化;③**合规与风险等级的变化**;④备选路径。
  **禁止静默替换。** 老板在 A 路径的信息下批准,却按 B 路径执行,等于决策前提被篡改——这比方案本身差更危险。
- **决策包内容**:待决策项 + 推荐选项 + 默认值 + 不决策的后果。
- **义务清单内容**:每项义务标注——什么时候要 / 多少钱 / 持续性(一次性还是订阅)/ 不提供会怎样。
- **一次收齐、一次拍板** → 解决"项目卡在老板这里"。
- **完成标准**:决策包发回后,无遗留 blocking 项;义务清单无"未知成本"死角;**路径降级项全部已上报且已获裁决**。

### S5 执行方案与红队评审 ◆角色隔离 · 预验尸 · 探针制
- **前半**:各岗位按流程协作产出执行方案(需求文档、技术方案、里程碑、验收标准)。
- **后半(红队岗,独立上下文,不看提案理由)**:
  - 审查:只看产物,输出评分与缺陷清单;
  - 预验尸:假设项目已失败,倒推死因,逐条生成预案;
  - **死因分级**:每条死因标注"纸面可论证"或"必须实验验证"。
- **探针(最小实验)** ◆v1.2:凡"必须实验验证"的致命不确定项(数据真实性、第三方行为、真实需求等),门 1 前用**有界成本的最小实验**消除——小样本、一次性、事先定好成本上限(如 ≤1 天 / ≤¥X)。结果回填决策包与义务清单,把隐患变成决策项。
- **探针护栏** ◆v1.3(防"探针变成无限研究",探针自己也需要护栏):开跑前必须书面声明三件事——①**要回答的问题**(一句话,可判真假);②**成本上界**(时间/金额/次数);③**判读标准**(什么结果算过、什么算不过)。**超界即停**,超界本身升级为决策项交老板裁定。没有这三项,不算探针,叫拖延。
- **产物**:执行方案 + 风险预案 + 探针结果。
- **完成标准**:缺陷清零或降级为"已接受的风险";每条死因有预案;**致命不确定项均已探针验证,或已列入条件 GO 的指定探针**。

### 【门 1】开工授权 = 正式立项
- **立项材料五件套**:开发指导文档 + 决策包(已拍板)+ **老板义务清单(已确认)** + 执行方案 + 风险预案。
- **产物**:**项目章程(Project Charter)**——注意,不是需求文档。
- **章程字段**:目标 / 范围边界(做什么、明确不做什么)/ 预算(必须覆盖义务清单的全部成本,含上线后的持续订阅)/ 里程碑 / 验收标准 / 责任人 / 风险与预案。
- **老板确认义务清单时必须明确**:哪些东西上线后我还要持续提供 / 持续付费。
- **老板三选一**:GO / 条件 GO / NO-GO。**条件 GO 的标准用法是"先跑指定探针"**——致命不确定项未经探针验证,不得无条件 GO;探针不过,项目不过。

### S6 开发交付 ◆变更与降级上报通道
- **执行方式**:分批执行,每批 = 一个可验收的最小交付单元;每批结束小评审(对照验收标准,红队岗复查)。
- **外部环境检查** ◆v1.3:每批小评审增加一项固定检查——**依赖的接口/平台政策/服务条款是否变化**?外部断裂(接口关闭、政策收紧、配额调整)是数据类与依赖型项目的头号突发死因,必须按批巡查而非等它爆。
- **新义务兜底**:开发中才冒出来的义务(API key、服务器、备案等)→ 更新义务清单,回流 S4 补评估;**影响预算 / 里程碑的 → 重过门 1**,禁止"先斩后奏地让老板付费"。
- **变更管理**:
  - 小变更(不影响章程范围)→ 记录即可;
  - 大变更(影响范围 / 预算 / 里程碑)→ 回退 S4/S5 重走,重过门 1。
  - **老板也是变更申请方,无例外** ◆v1.3:老板中途加需求/改需求,同样走本通道——**没有"老板特权"**。老板一句话的成本,最终由项目预算承担。
- **常见坑**:口头改需求——必须走变更通道。

### 【门 2】验收发布
- **动作**:对照章程验收标准逐条核验。
- **老板二选一**:GO(发布)/ 返工(附缺陷清单)。
- **收尾**:全流程产物归档,沉淀为下一个项目的模板资产。

## 5. AI 特有机制(八件套)

| 机制 | 解决的问题 | 规则 |
|---|---|---|
| 复述确认制 | 颗粒度错位 | AI 复述需求,老板确认后才进入下一步 |
| 决策包制 | 老板成瓶颈 | 决策批量收齐,每项带推荐 + 默认值 |
| 决策点标注 | 决策权模糊 | 指导文档区分"老板定"与"AI 自主" |
| 义务清单制 | 隐性成本突袭老板 | 外部依赖与付费义务强制成清单,门 1 一并确认;开发中新义务回流评估 |
| 角色隔离制 | AI 自己论证自己 | 提案与审查分离上下文;**隔离方式必须声明,做不到就标注可信度打折** ◆v1.3 |
| 预验尸 | 风险清单太温吞 | 从"已失败"倒推,逼出真死因;死因分级:纸面可论证 / 必须实验验证 |
| 探针制 | 纸面分析无法验证的致命不确定项 | 最小实验、有界成本,门 1 前消除;开跑前声明问题/上界/判读标准 ◆v1.3 |
| 变更与降级上报通道 | 范围蔓延 + 方案静默降级 | 大变更重走流程;**路径降级必须显式上报**(原因/成本/合规等级/备选) ◆v1.3 |

**分析不能替代实验。** 纸面流程(S0–S5)的价值不是省掉实验,而是把"哪些不确定性必须用实验消除、什么时候消除最便宜"排出来——并把发现时点强制提前到花钱开发之前。

**与真人团队的三点本质差异**:
1. 真人团队"人时"贵,这里"决策带宽"贵 → 一切设计围绕批量决策。
2. 真人怕岗位冗余,这里虚拟岗位零成本 → 岗位越专越好,唯一约束是审查隔离。
3. 真人靠会议对齐,这里靠文件对齐 → **产物即沟通**。

## 6. 颗粒度对齐规则(本流程的核心目标)

**老板侧**:
- 输入颗粒度只有三种:想法(3 句)/ 决策(选项 + 默认值)/ 验收(标准)。
- 超出此颗粒度的细节,AI 不得要求老板提供;AI 自行给假设并在产物中显式标注。

**AI 侧**:
- 每阶段一个文件、一页可读;超一页必须拆两级。
- **结论前置** ◆v1.3:每份产物开头必须有**一句话结论 + 三行要点**;找不到结论的文档视为不合格,打回重写。**没人读的文档等于没写**——产物的价值在信息密度,不在篇幅。
- 禁止用 20 轮小问题追问老板 → 必须合并为一份补问清单 / 决策包。
- 所有假设显式列出,不藏在正文里。
- **并行项目标注与闸门** ◆v1.3:决策包与义务清单必须标注所属项目;老板**同时待决项上限 15 条**,超限排队——注意力一旦被切片,决策质量就会塌。

**双向禁止**:
- 老板在 S3 之后直接口头改需求细节 → 走变更通道。
- 任何一方跳过门催进度 → 门是止损点,不是拖延。

## 7. 裁剪细则(分档见 §0,本节只列追加项)

| 档 | 追加 / 裁剪 |
|---|---|
| 微、小 | 见 §0.2,不在此重复 |
| 中 | 全流程默认;S2 可压缩为半页竞品速查 |
| 大 | 增设门 1.5(技术方案评审);S4 按模块拆分;预验尸与探针逐模块执行 |

**三条裁剪原则**:
1. **阶段可合并、可轻量;门不能删。** 删门 = 删止损点。
2. **流程能砍,原则不能砍。** 即使走微项目档,路径降级仍须告知、结论仍须前置、要你出的钱与账号仍须说清。
3. **档位宁可定高半档,不可定低半档。** 升档的成本是几轮对话;降档出错的成本是返工甚至废弃。

## 9. 消歧:易混淆判据的统一口径 ◆v1.5

| 易混情形 | 判定 |
|---|---|
| 周末工具用一个免费 API key | **小**档(Q1 为是,但单个非生死依赖不抬中档) |
| 项目数据源是某平台,平台一封项目就死 | **中**档起(关键路径外部依赖) |
| 预计 1 周,做着做着发现要 2 周半 | **升档**到中,按 §0.4 补差额 |
| 老板说"先做做看,不行就算了" | 不影响定档;定档看客观判据,不看心态 |

## 8. 附录:模板


### F. 老板义务清单(S4 产物,门 1 确认)
